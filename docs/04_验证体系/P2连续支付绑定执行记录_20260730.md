# P2 连续支付绑定执行记录

> 日期：2026-07-30
> 状态：PASS
> 范围：离线协议中立实验，不执行真实支付

## 1. 本轮目标

P2 把 P1 的确认链继续延伸为：

```text
Delegated Authority
    → Confirmed Order
    → Payment Request
    → Payment Execution
```

重点回答：最终计划执行的 Payment 是否仍然来自刚刚核验的授权、订单和支付请求。

## 2. 已实现能力

- `TransactionRequest` 增加 `order_ref`、`authority_ref`、`authority_version_ref` 和 `payee`；
- `PaymentExecutionRecord` 增加 `authority_ref`、`agent_ref`、`transaction_object_ref` 和 `payee`；
- `verify_payment_execution_binding()` 同时核验两段引用、金额、币种、收款方、执行标识与时序；
- 缺少必要引用返回 `MISSING_EVIDENCE`，引用或关键字段冲突返回 `INVALID`；
- `execute_with_payment_binding_gate()` 重新计算 P2 事实，只有上游决策为 `ALLOW` 且 P2 为 `VALID` 时才调用支付回调；
- S10/S11 生命周期与 S12 UNKNOWN 恢复已消费相同 P2 证据，技术详情 UI 可以读取绑定状态和引用链。

## 3. 负向验收

专项测试已覆盖：

- Payment Request 错绑其他 Order；
- Payment Execution 错绑其他 Request / Order；
- 授权或 Agent 引用被替换；
- amount / currency / payee 被替换；
- 连续引用缺失；
- payment_id 与 request_id / order_id 冲突；
- 执行时间早于请求；
- 上游为 `DENY / CONFIRMATION_REQUIRED / INDETERMINATE` 时禁止调用回调。

P2 核心结果：`8 passed, 3 subtests passed`。

P2 核心、生命周期、恢复、主结果与最小 UI 契约结果：`60 passed, 130 subtests passed`。

## 5. 边界

P2 证明的是固定离线对象之间的确定性连续关系，不证明：

- 支付机构记录或确认记录不可篡改；
- Agent / Executor 已完成真实身份认证；
- 回调对应真实扣款、清算或资金终局性；
- 满足生产安全、合规或审计要求。
