# 《智能体支付应用自律公约》开发指标映射 v1

## 1. 用途

本文将《智能体支付应用自律公约》转成 `agentic-payment-trust-lab` 的外部开发 / 验证指标。

它不是合规结论，也不是把 34 条机械变成 34 个功能，而是用于：

```text
条款
  -> 能力族
  -> 项目适用性
  -> 当前对象 / 模块
  -> Test
  -> Evidence
  -> Gap
```

## 2. 状态枚举

### 2.1 适用性

- `CORE`：项目应直接具备并验证。
- `ADAPTER`：项目应接入 / 承载外部事实。
- `EVIDENCE_ONLY`：项目主要负责记录和证明。
- `REFERENCE_ONLY`：组织 / 法律 / 运营要求，作为设计审查参考。
- `OUT_OF_SCOPE`：明确不属于项目实验范围。

### 2.2 成熟度

- `M0 MISSING`
- `M1 MODELLED`
- `M2 IMPLEMENTED`
- `M3 TESTED`
- `M4 EVIDENCED`
- `M5 REGRESSION_GATED`

## 4. 项目级开发指标

| 指标 | 目标 |
|---|---|
| `applicable_requirement_count` | 明确真实适用项，避免把组织要求伪装成代码覆盖 |
| `modelled_requirement_rate` | CORE 要求是否都有领域对象 / Contract |
| `tested_requirement_rate` | CORE 要求是否都有确定性测试 |
| `evidenced_requirement_rate` | CORE 要求是否能产生端到端 Evidence |
| `regression_gated_rate` | 已验证能力是否进入持续回归 |
| `critical_gap_count` | 高风险 M0 / M1 缺口数量 |
| `model_risk_gap_count` | 模型风险未覆盖项 |
| `revocation_recovery_gap_count` | 撤销 / 关闭 / 应急 / 恢复未覆盖项 |
| `cross_agent_gap_count` | 跨 Agent 场景未覆盖项 |
| `privacy_gap_count` | 数据最小化 / 隐私未覆盖项 |

## 5. 当前优先缺口

建议优先检查以下 8 项，而不是继续随机增加攻击 Case：

1. KYA Profile + Agent Risk Tier；
2. Agent Identity 全链路传递；
3. Authorization Lifecycle + Revocation；
4. Cross-Agent 调用与大额交易；
5. Model Risk Profile；
6. Continuous Monitoring Facts；
7. Emergency Stop / Fallback；
8. Data Minimization / Privacy Fact。

## 7. 使用原则

- 不追求“34/34 都写代码”。
- `CORE` 才进入强制开发 / 回归指标。
- `ADAPTER` 强调外部系统边界。
- `REFERENCE_ONLY` 只做设计审查。
- 任一 `CORE` 项声称 Covered 时，必须同时能指出：**对象 / 代码 / Test / Evidence**。
