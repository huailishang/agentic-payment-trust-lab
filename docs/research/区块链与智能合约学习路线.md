# 区块链与智能合约按需学习路线

> 状态：`REFERENCE_ONLY（只参考）`。2026-08-27 起，Blockchain（区块链）不属于项目主线，只作为 Payment Trust / Security 的按需技术来源。系统性的密码学与可信执行仍在主仓库 `agentic_payment_experiment.trusted_execution` 内验证；本文件只保留“什么真实问题才值得学习哪项机制”的索引，不驱动链上开发。

## 1. 当前决策：一仓两域，业务问题按需调用可信能力

区块链、智能合约、稳定币和代币化存款与部分智能体支付轨道有关，但**不是智能体支付可信的默认底座**。项目先用普通签名、数据库审计、幂等键、现有支付网络和确定性状态机解决问题；只有跨主体可验证交易、钱包 / 密钥、链上最终性或结算证据等真实需求证明这些机制不足时，才进入区块链学习。主仓库内部仍保持支付域与可信执行域两个职责域：支付域负责业务生命周期和业务裁决，可信执行域负责哈希（Hash）、签名、对象绑定、幂等、状态验证和审计等确定性验证能力。

后续原则是：支付场景提出明确可信问题时，由支付域单向调用 `agentic_payment_experiment.trusted_execution` 的稳定组件，把验证事实转换为本项目自己的业务裁决。可信执行组件不得反向修改 Mandate、Order、支付生命周期或四态决策语义。

## 2. 学习原则

- 从支付 / Security 真实问题出发，不按公链生态或热门项目罗列课程。
- 每个候选先回答“普通签名、数据库审计、幂等键或现有支付网络为什么不够”；回答不了则 `REFERENCE_ONLY`。
- 先理解交易状态、签名、幂等和终局性；只有真实场景必须链上确定性执行时才研究智能合约。
- 先使用本地模拟和固定数据，不使用真实资金、主网资产或生产密钥。
- 智能合约只执行确定条件；语言模型不得决定不可逆资金转移。
- 学习产出必须说明适用范围和不能推出的生产结论。

## 3. 模块与触发条件

| 学习包 | 触发场景 | 核心问题 | 最小产出 |
|---|---|---|---|
| BC-01 账本与交易生命周期 | 只有进入 x402 / MPP / 代币化结算等账本轨道比较时；普通 S05 / S12 不自动触发 | nonce、确认、终局性、重组、费用和状态未知有什么区别 | 状态图、术语映射和一个本地重试样品 |
| BC-02 签名与对象绑定 | 出现真实签署者 / Credential / 钱包密钥关系时；S09 / S13 可先用普通哈希与 Binding | 如何证明委托、订单、收款方和请求未被替换 | 哈希/签名边界说明和固定签名测试；不接真实凭证 |
| BC-03 智能合约状态机 | 只有明确需要链上托管、条件释放或可验证合约执行时 | 托管、条件释放、退款、事件日志和失败恢复如何表达 | 与普通确定性状态机对照；证明智能合约确有新增价值后才做最小伪合约 |
| BC-04 Token与可编程钱包 | x402 / MPP 或真实 Agent Wallet 授权问题进入后 | Token授权、permit、账户抽象、消费限额和会话权限如何工作 | 与中立委托模型的字段映射和风险清单 |
| BC-05 结算资产与治理 | 路线比较 | CBDC、代币化存款和稳定币由谁负债、谁治理、如何赎回 | “负债主体×账本治理”比较表 |
| BC-06 Oracle、桥和跨链 | 只有明确跨链场景时 | 外部事实和跨链消息为何引入新信任与恢复风险 | 威胁模型；当前不实现桥或Oracle |

学习顺序由场景触发，不要求从BC-01连续学到BC-06。当前I2最多按需使用BC-02中的对象摘要和绑定概念，不因此启动链上开发。

## 4. 允许与禁止的实验

允许：

- 纯本地、可删除、无真实价值的交易状态模拟。
- 固定私钥或测试向量的签名验证，但不得与个人或生产身份关联。
- 用最小合约理解状态机、事件、回退和幂等。
- 比较EVM、联盟链或中心化账本如何表达同一支付问题。

禁止：

- 主网或测试网上持有、转移真实价值。
- 保存助记词、生产密钥、卡凭证或客户身份。
- 创建代币、钱包产品、跨链桥或投资策略作为项目目标。
- 因学习了某条链就将其中立字段或治理假设写入核心模型。

## 5. 何时重新评估公共平台化

可信执行已经作为主仓库内的独立职责域存在，但仍不等于要建设公共平台。只有同时满足以下条件，才向总控评估公共开发工具包（SDK）、服务化或更强治理：

1. 至少两个独立项目 / 场景持续复用同一组哈希、签名、幂等、状态机或审计组件，证明它不是支付场景专用实现。
2. 已形成不依赖智能体支付场景的可运行资产，而不是资料汇编。
3. 有明确使用者、问题、验收方式、维护责任和停止条件。
4. 独立安全、依赖或发布治理已超出单一学习实验仓库的合理边界。
5. 平台化不会挤占信用卡经营主线和当前支付实验任务。

在此之前，可信执行项目首先是学习与实验仓库；区块链仍是一组可被金融智能体问题调用的技术思想和组件，不是新的创业方向。
