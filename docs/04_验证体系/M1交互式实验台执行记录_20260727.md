# M1 交互式实验台执行记录

> 日期：2026-07-27

## 1. 目标

把现有 S01—S13 从“固定 JSON -> 生成静态报告”推进为：

```text
选择场景
    -> 修改少量关键业务条件
    -> 点击执行验证
    -> 本地 Python 后端重新计算
    -> 页面显示新的决策 / 生命周期 / 支付恢复结果
```

本轮只解决交互闭环，不新增真实支付，不扩充 S14，也不提前设计大量协议字段。

## 2. 实现

### 2.1 仍然只有一套正式界面

没有建立第二套 UI。

原来的 `scenario_report.html` 同时支持：

- 直接打开：静态报告模式。
- `python run_experiment.py --serve --open`：交互实验模式。

交互模式通过本机 HTTP API 调用 Python 规则重新计算，不在浏览器里复制一套判断逻辑。

### 2.2 S01—S13 全部提供少量关键可编辑字段

每个场景最多 3 个主要输入，避免 UI 再次被技术字段淹没。

示例：

```text
S02：实际支付金额 / 用户授权上限
S05：request_id 是否已经处理过
S08：实际金额 / 人工确认阈值 / 绝对上限
S09：用户确认金额 / 最终订单与支付金额
S10：支付状态 / 履约状态
S11：履约状态 / 退款状态 / 退款金额
S12：查询到的原交易状态 / 幂等键 / 其他支付尝试
S13：授权 Agent / 实际 Agent
```

协议字段、证据、原始 JSON 等没有删除，但界面入口从“查看关键环节技术细节”降级为默认折叠的“开发者信息（可选）”。

### 2.3 本地接口

新增：

```text
src/agentic_payment_experiment/interactive_lab.py
src/agentic_payment_experiment/interactive_server.py
```

接口：

```text
POST /api/evaluate
```

只接受每个场景白名单中的可编辑字段；未知字段直接拒绝。

默认监听：

```text
127.0.0.1:8765
```

不接银行卡、商户、支付网络或生产凭证。

## 3. 关键人工验证

已验证输入变化会真实改变 Python 结果：

```text
S02  560 -> 480
DENY -> ALLOW

S08  520 -> 480
CONFIRMATION_REQUIRED -> ALLOW

S13  agent-shop-other -> agent-shop-001
DENY -> ALLOW

S09  最终订单/支付金额 490 -> 480
CONFIRMATION_REQUIRED -> ALLOW
```

S12 也验证了恢复分支：

```text
查询原交易 = FAILED
+ 有幂等边界
+ 无其他成功/未决尝试
-> RETRY_CANDIDATE

查询原交易 = FAILED
+ 已存在同请求成功尝试
-> BLOCKED

查询原交易 = FAILED
+ 缺少幂等键
-> BLOCKED
```

这里的 `RETRY_CANDIDATE` 仍只表示可以进入业务重试候选，不执行第二笔支付。

### 3.1 矩阵与关键环节联动

2026-07-27 补齐 M1 联动收口：交互输入改变后，不只更新顶部结果，还会用当前 Python 结果重新生成支付生命周期矩阵和“当前场景关键环节”。

```text
修改关键条件
    -> Python 重新计算
    -> 决策 / 生命周期 / 支付恢复结果更新
    -> 矩阵坐标更新
    -> 支付主线与可信执行侧支更新
    -> 订单差异表同步更新
```

已验证：

```text
S02：560 -> 480
F1 权限异常 -> NONE 正常基线

S09：最终金额 490 -> 480
L3 × F3 -> L4 × NONE

S10：履约 FAILED -> SUCCEEDED
L7 × F6 -> L9 × NONE

S12：查询 FAILED + 已有同请求成功尝试
L5-L6 × F5 -> L5-L6 × F4 重复/幂等异常
```

点击“恢复样品值”后，矩阵与关键环节一起恢复到固定样品状态。

## 5. 当前边界

M1 现在证明的是：

> 同一个场景的关键输入发生变化时，系统可以通过真实 Python 规则重新计算，而不是只展示预先写死的结果。

它仍不能证明：

- 当前业务规则就是现实支付最佳规则。
- 当前场景足够覆盖真实风险。
- 银行、商户或卡组织可以直接采用。
- 真实 Agent 在复杂环境下不会被攻击或误导。

这些问题进入 M3 外部挑战、M4 协议集成和 M5 统一评测解决。
