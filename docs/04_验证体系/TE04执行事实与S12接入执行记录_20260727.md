## 2. 本轮新增接口

新增 `trusted_execution/execution_facts.py`：

```text
verify_execution_identity(...)
    -> VALID / INVALID / MISSING_EVIDENCE

validate_status_observation(...)
    -> VALID / INVALID / MISSING_EVIDENCE

check_idempotency(...)
    -> 幂等边界是否存在
    -> 同一 request_id 的相关执行尝试
    -> 哪些尝试使用相同幂等键
    -> 哪些尝试使用不同或缺失幂等键
```

统一结构：

- `VerificationStatus`
- `VerificationResult`
- `ExecutionAttemptFact`
- `IdempotencyFact`

### 最重要的设计边界

```text
IdempotencyFact = VALID
≠ 可以重试
≠ 可以再次扣款
≠ 支付一定安全
```

`VALID` 当前只表示：**原支付存在显式幂等键，且可信执行层能够据此整理相关执行事实。**

是否进入 `RETRY_CANDIDATE`，仍由支付域继续结合：

- 原支付最终状态是否确认失败；
- 是否已经存在成功尝试；
- 是否仍有 UNKNOWN / PENDING 尝试；
- 状态观察是否可靠绑定原交易；
- 幂等边界是否存在。

## 3. S12 如何接入

原链路：

```text
payment_recovery.py
    -> 自己比较 payment_id / order_id / provider_ref
    -> 自己筛选同 request_id 的其他支付尝试
    -> 自己判断是否存在 idempotency_key
    -> 再进入恢复策略
```

当前链路：

```text
PaymentExecutionRecord
+ PaymentStatusObservation
        ↓
Trusted Execution
validate_status_observation()
        ↓
状态观察绑定事实
        ↓
Payment Domain
保持原有 SUCCEEDED / UNKNOWN / PENDING / FAILED 恢复分支

FAILED 分支：
known_attempts
        ↓
Trusted Execution
check_idempotency()
        ↓
幂等边界 + 同请求相关尝试事实
        ↓
Payment Domain
继续判断：
已有成功尝试？
仍有未知/处理中尝试？
缺少幂等边界？
否则才进入安全重试候选
```

## 5. 关键负向验证

### 5.1 状态观察引用错交易

```text
payment_id / order_id / provider_ref 不匹配
    ↓
TE04 = INVALID
    ↓
Payment Domain = BLOCKED
    ↓
禁止重试，进入引用关系调查
```

保持原 S12 语义不变。

### 5.2 有幂等键，但已经存在成功支付

```text
幂等边界 = VALID
同 request_id 已存在 SUCCEEDED 尝试
    ↓
Payment Domain = BLOCKED
retry_allowed = false
```

这条测试证明：

> **幂等事实通过不等于业务上允许重试。**

### 5.3 有幂等键，但仍有 UNKNOWN / PENDING 尝试

```text
幂等边界 = VALID
同 request_id 仍有 UNKNOWN / PENDING
    ↓
Payment Domain = BLOCKED
    ↓
先查询已有尝试，不创建新的扣款风险
```

### 5.4 FAILED + 无冲突尝试 + 显式幂等边界

```text
状态观察可靠
+ 原支付确认 FAILED
+ 无成功并行尝试
+ 无 UNKNOWN / PENDING 并行尝试
+ 幂等边界存在
    ↓
Payment Domain = RETRY_CANDIDATE
```

这里只进入“安全重试候选”，项目仍不会执行真实第二次支付。

## 6. 外部规范核对

本轮只做有范围的官方资料核对，不克隆、不安装、不接入第三方实现。

| 来源 | 本项目采用点 | 明确不采用 / 不宣称 |
|---|---|---|
| RFC 9110 HTTP Semantics | 采用“幂等关注重复相同请求的预期效果”这一基础概念 | 不把 HTTP 方法幂等性直接等同于支付业务可重试 |
| IETF `Idempotency-Key` Internet-Draft | 借鉴显式幂等键用于关联重复请求、避免无意重复处理的方向 | 截至本轮核对该文档为已过期 Internet-Draft，因此不宣称遵循某个已发布 RFC |
| Stripe 官方 Idempotent Requests 文档 | 参考支付服务商用客户端幂等键识别重试、避免重复创建操作的工程实践 | 不复制 Stripe 的保存期限、参数比较、错误缓存等供应商特定语义 |

访问日期：2026-07-27。

本轮没有新增外部运行依赖、SDK、网络服务、密钥或凭证。
