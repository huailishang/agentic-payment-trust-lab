## 全局作用与唯一目标

项目从“自己能运行”推进到“别人能核对”。消费已验收的 H42/H44 快照，形成一个可在干净目录离线校验输入、重新计算判定和指标的可分发包。主要变化只有证据与复跑包装，不修改支付规则，也不将包装成功记为安全能力提升。

没有接受 H44 结果前，不跳过外部对照只包装本地 H42 就宣称目标完成。

## 冻结前的精确缺项

1. H42 已有接受快照、正式 REVIEW 与 L2/L3；H44 仍缺已接受快照、正式 REVIEW、原始逐运行记录、明确边界与失败登记。H42 原材料也尚未经过可分发包的脱敏、许可与可移植性审查。
2. 选定外部 source/依赖的合法分发方式：许可允许的最小文件、完整许可证与通知，或固定哈希的离线依赖清单；不得默认整个仓库/日志可复制。
3. 选定干净运行环境及必要依赖的离线提供方式；不得用执行者机器的绝对路径冒充可移植环境。
4. 从已接受快照确定 manifest 与预期可重算结果；Evaluator 冻结完整性、负例和安全检查器及 exact argv，生成正式 VALIDATION_PLAN.yaml。

## 输出合同

拟议本地归档根目录：artifacts/replay_bundles/<bundle-id>/，不强制加入 Git。

| 资产 | 必须包含 |
|---|---|
| README.md | 大白话目的、前置条件、离线核对命令、预期输出、失败含义、测量层级 |
| MANIFEST.json | 相对路径、SHA-256、来源与基线、包版本、依赖与许可；覆盖全部分发成员，不允许额外未登记文件 |
| sources/ 与 licenses/ | 允许分发的最小固定来源及许可；本项目派生内容显式标识 |
| inputs/ 与 records/ | 冻结输入、脱敏调用/状态记录、成功和失败；无实际凭据和原始思维链 |
| verify_bundle.py | 校验清单及来源锁，离线重算决策/指标；缺失、篡改、路径越界和额外文件均失败关闭 |
| EXPECTED_RESULTS.json | 来自已接受证据的结果，不能先写期望成功再倒填记录 |
| LIMITATIONS.md | 合成/上游/模型/Provider 边界、样本与随机性、未验证项、失败与无收益结果 |

允许包内必要的项目模块最小快照，但必须登记基线和哈希，不形成另一套维护分叉，不复制完整 dirty worktree（含既有未提交改动的工作区）。如通过补丁复现，必须纳入已接受的未提交实现；仅记录 Git HEAD 不足以复现当前 H43 等继承改动。
