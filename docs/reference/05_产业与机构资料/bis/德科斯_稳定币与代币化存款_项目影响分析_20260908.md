# 德科斯“稳定币与代币化存款”对项目的影响分析

> 日期：2026-09-08  
> 来源级别：A级 / 公共部门正式研究与管理层讲话  
> 项目结论：`ABSORB（吸收架构边界）`，但**不改变当前 B-12 / H-18 冻结主线**。

## 2. 先收敛原文结论

德科斯的核心比较不是“区块链 vs 银行”，而是不同数字货币安排能否继续满足货币体系的基础属性：

```text
共同记账单位
+ Singleness（单一性 / 平价可兑付）
+ Interoperability（互操作性）
+ Financial Integrity（金融完整性）
+ 最终以可信结算资产完成结算
```

其判断是：

- 当前稳定币可以利用 Tokenisation（代币化）和 Programmability（可编程性），但不同稳定币、不同链及二级市场兑换会带来平价偏离和碎片化，缺少一个自动强制“单一性”的机制；
- 代币化存款仍是商业银行负债，如果银行间通过央行货币 / 央行准备金完成最终结算，更容易延续现有两层货币体系的平价关系；
- 自托管钱包、点对点转移和公共链环境会增加 AML/CFT（反洗钱 / 反恐融资）执行难度；
- BIS 并非否定 Tokenisation，本身正在通过 Project Agorá 验证“代币化商业银行存款 + 代币化央行准备金 + 可编程共享平台”；
- 2026 年 Project Agorá 已完成原型，并于 2026 年 7 月完成真实价值测试，说明这一方向已从纯概念进入受控实证阶段。

需要保留证据边界：这不等于“BIS 禁止稳定币”，也不等于“代币化存款已经形成成熟的跨银行、跨司法辖区生态”。德科斯本人明确承认现实互操作生态仍未成熟。

## 3. 对本项目最重要的架构校准

项目现有“协议 / 支付工具 / 支付轨道 / 结算资产”分层继续成立，但 Cross-Rail（跨支付轨道）不能只理解成替换一个 `rail` 字段。

更准确的链路是：

```text
User Authority / Mandate
        ↓
AP2 / ACP / UCP / x402 等协议表达
        ↓
Payment Instruction
        ↓
Payment Instrument / Funding Source
        ↓
Payment Rail / Network
        ↓
Settlement Asset
        ↓
Finality / Redemption / Recovery / Governance
```

其中：

- Agent Trust Control（智能体信任控制）回答“这笔钱该不该花、谁有权花”；
- Payment Rail（支付轨道）回答“支付指令通过什么系统执行”；
- Settlement Asset（结算资产）回答“最终用什么货币性资产清偿、谁承担兑付义务”；
- Finality / Recovery（最终性 / 恢复）回答“什么时候真正结束、状态异常后如何安全恢复”。

因此，同一个 `amount=100`、`currency=USD` 并不能自动说明 100 美元银行存款、100 USDC、100 USDT、不同链上的同名稳定币或代币化存款具有完全相同的结算风险。

## 4. Cross-Rail 的后续验收应拆成两层

### 4.1 Shared Trust Invariants（共享信任不变量）

无论选择哪条支付轨道，以下控制原则应保持一致：

```text
Identity
→ Authority
→ Order / Payment Binding
→ Budget / Scope
→ Human Confirmation
→ Idempotency
→ Evidence / Replay
```

要验证的是：Agent 不能因为切换银行卡、账户、稳定币或其他轨道而绕过用户委托和副作用前治理。

### 4.2 Rail / Asset-specific Finality（轨道 / 资产特定最终性）

不能要求所有轨道硬塞进同一套最终性语义。后续至少要允许区分：

```text
轨道 / 网络状态
结算资产类型
发行方 / 负债主体
最终结算锚
平价赎回机制
结算最终性证据
异常查询来源
退款 / 撤销 / 恢复机制
```

这是一项**未来建模要求**，当前不因此立即给 Payment 对象增加大量字段。只有 Cross-Rail 升为第一瓶颈并出现可证伪实验时，再冻结最小 Contract。

## 5. x402 的边界进一步明确

本项目继续保持：

```text
x402 ≠ Stablecoin
x402 ≠ USDC
x402 ≠ Blockchain
x402 ≠ Future Money
```

x402 主要表达 HTTP / API 资源如何提出支付要求、提交支付载荷并验证 / 结算；当前生态常与链上稳定币结合，但 Settlement Asset（结算资产）是下层选择，不应反向绑死上层机器支付协议。

因此，未来机器资源支付仍可研究：

```text
Metering
→ Authorization Cap
→ Charge
→ Settlement
→ Service Delivery
→ Recovery
```

但不把“x402 + stablecoin”写成智能体支付的唯一目标架构。

## 6. Financial Integrity（金融完整性）如何吸收

BIS 对 AML/CFT、自托管钱包和钱包间转移的关注对项目有价值，但当前项目不自行实现“AML 规则引擎”或伪造生产合规能力。

后续正确边界是：

```text
External Authoritative Compliance Source
        ↓
KYC / Sanctions / Wallet Screening / Institution Eligibility Fact
        ↓
Fact Lineage
        ↓
Runtime Gate
        ↓
Decision / Evidence
```

也就是：外部权威系统产生合规事实，本项目负责确保 Agent、网页、模型或工具不能静默篡改、覆盖或绕过这些事实。

## 7. 对当前主线的裁决

当前 B-12 / H-18 继续不变：

```text
Same-Journey Payment Lifecycle
→ UNKNOWN / Query Recovery
→ Fulfillment Failure
→ Status Conflict
→ Finality / Recovery Continuity
```

原因是 BIS 材料没有证明当前第一瓶颈改变；相反，它强化了 Payment Finality / Recovery 是未来多轨道和可编程支付共同需要的底座。

所以当前路由是：

```text
先完成 B-12
→ 把当前支付生命周期连续性测清楚
→ 未来 Cross-Rail 升级时
→ 再引入 Settlement Asset / Finality 差异作为实验变量
```

## 8. 项目长期原则

> **Agent 支付控制解决“这笔钱该不该花”；支付轨道解决“钱怎么走”；结算资产解决“最终收到的到底是什么钱、由谁保证、什么时候真正结束”。三者不得混为一层。**

该原则用于后续 Cross-Rail、x402、银行卡 / 账户、数字人民币、稳定币和代币化存款研究的统一边界。
