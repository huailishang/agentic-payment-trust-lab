# 横向攻击验证轨 / Adversarial Security Validation Track

Status: `ACTIVE_CROSS_CUTTING_WATCH`
Owner: Evaluator
Applies to: B-02 / B-04 / B-06 / B-15 and future external-provider tasks

## 1. 定位

这不是第二套支付主线，而是一条**横向安全验证轨**：

```text
纵向主线：
AP2 → Alipay Sandbox → 其他真实 Provider

横向攻击轨：
固定负例 → Prompt/Tool/Context 攻击 → 自适应模型红队 → 跨协议攻击
```

目标不是“证明模型不会被骗”，而是验证：

> 即使 Agent/LLM 被诱导、上下文被污染、工具返回恶意内容、攻击模型主动寻找绕过点，真正产生支付/履约/退款等高风险副作用前，Trust Control Plane 仍能 fail closed(失败时关闭)、要求确认、保留证据。

## 2. 与传统网络安全的关系

本项目不取代主机、网络、漏洞、恶意代码、供应链安全。

本横向轨重点覆盖 Agentic Security(智能体安全) 与 Transaction Trust Security(交易信任安全) 的交界：

- Prompt Injection(提示注入)
- Tool Output Manipulation(工具输出篡改)
- Context Poisoning(上下文污染)
- Credential / Identity Confusion(凭证/主体混淆)
- Authorization Escalation(授权越权)
- Order / Amount / Merchant Rebinding(订单/金额/商户错绑)
- Replay / Duplicate Side Effect(重放/重复副作用)
- Evidence Tampering(证据篡改)
- Secret Exfiltration Attempt(秘密信息外泄尝试)

## 3. 分阶段能力

### X0 — Deterministic Attack Overlay【已有基础】

已有 Attack Overlay `6/6 PASS`、AP2 negative cases、replay/binding/source-integrity 等确定性负例。

作用：回答“已知攻击是否能机械阻断”。

### X1 — Agent-facing Adversarial Fixtures【下一阶段候选】

构造恶意网页、恶意工具返回、Prompt Injection、伪造支付成功、金额/商户替换、旧授权重放。

作用：回答“攻击发生在 Agent 上游时，Trust Gate 是否仍不被绕过”。

要求：
- 完全本地或 Sandbox；
- 无真实凭证/资金；
- 攻击目标仅限本项目自己的受控环境。

### X2 — Adaptive Model Red Team【后续候选】

使用一个强模型作为 attacker agent(攻击智能体)，只给它：
- 受控目标；
- 允许的工具；
- 固定预算；
- 禁止真实外部攻击；
- 禁止生产凭证；
- 禁止真实支付。

让攻击 Agent 自适应尝试绕过：
- 用户授权；
- amount/merchant/order binding；
- confirmation gate；
- replay protection；
- provider result verification；
- trace/evidence integrity。

作用：从“我们事先想到的攻击”升级为“攻击模型主动寻找我们没想到的绕过路径”。

### X3 — Cross-Provider Adversarial Evaluation【外部协议阶段】

在 AP2 / Alipay Sandbox / 后续 Provider 上复用同一攻击类别，验证 Trust Core 是否协议中立。

重点不是比较协议谁更安全，而是看：
- 同一类攻击是否被同一个 Core rule 阻断；
- 是否出现 provider-specific 绕过；
- 是否为了适配 Provider 把安全规则散落到 adapter。

## 4. 核心指标

第一阶段只用少量可机械复核指标：

- unauthorized_side_effect_rate：未授权副作用率，目标 0；
- attack_bypass_rate：攻击绕过率，目标 0；
- confirmation_miss_rate：应确认却未确认，目标 0；
- replay_acceptance_rate：重放接受率，目标 0；
- binding_mismatch_acceptance：错绑接受率，目标 0；
- secret_exposure_count：敏感信息泄露次数，目标 0；
- evidence_corruption_acceptance：证据篡改被接受次数，目标 0；
- benign_task_regression：正常任务回归，不因过度防御大幅恶化。

## 5. 任务优先级

当前不抢占 H-38 主线。

```text
当前：
H-38 Alipay Sandbox first external slice  [ACTIVE NEXT]

横向：
X0 deterministic attacks                  [BASELINE EXISTS]
X1 agent-facing adversarial fixtures       [WATCH / NEXT AFTER FIRST LIVE SLICE]
X2 adaptive model red team                 [DEFERRED]
X3 cross-provider adversarial eval         [DEFERRED]
```

原因：先拿到第二个真实 Provider 的最小可验证链，再用横向攻击轨打这条链，信息增益更高。

## 6. 红线

横向攻击验证只允许攻击**自己的本地实验环境或明确授权 Sandbox**。

禁止：
- 对第三方生产系统做扫描、漏洞利用或未经授权测试；
- 使用生产账号/密钥/PII；
- 真实资金攻击实验；
- 让攻击模型自由访问互联网目标；
- 把“模型能攻击”当作绕过项目权限边界的理由。
