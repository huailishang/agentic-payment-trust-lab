## 建议下一包的单一能力假设（有条件，尚未冻结）

工作名称：**B-24 Consumer Use-Time Qualification and Provenance Gate（使用时点与来源资格门禁）**。

可证伪假设：让身份消费链明确接收**具备来源及有效期语义**的使用时点资格输入，并在离线可信输入资格不成立时禁止事实从 `BOUND` **升级为 `VERIFIED`**，能降低“历史已验证事实被当成当前强身份保证”的本地可复现错误，同时不破坏 P3 既有 `BOUND/VERIFIED` 业务准入。

**唯一主要变化**是“VERIFIED 晋级资格检查”而不是新证书服务、全局撤销数据库、P3业务策略变更或重写认证系统。实现应放在已有消费与支付门禁之间，使用既有`verify_agent_executor_identity` / `execute_with_payment_binding_gate` 路由；不得复制现有证书有效期、挑战年龄、Nonce、revoked状态或三元归属逻辑。

### 冻结前必须解决的接口语义

- `observed_at_epoch`（捕获/验签时刻）与 `use_time_epoch`（使用时点）不同。调用者声称的系统当前时间本身**不是**真实权威事实；禁止仅凭一个可伪造时间字符串将旧凭据重新晋级VERIFIED。
- 权威凭据的状态应包括：`credential_ref`、Agent/Provider/Executor归属、上游证明来源、状态版本/查询时点、事实有效截止/撤销及轮换证据、使用时点资格结果及理由；本地可用合成输入用于测试接口，但标记 `synthetic`，不能据此标真实已验签。
- 对缺失、过期、撤销、轮换、错绑、未来时间/时钟回退，明确 `INVALID` / `BOUND` / `NOT_JUDGEABLE` 的边界；**绝不悄悄晋级 VERIFIED**。应保留真实上游的 `UNKNOWN`，没有权威数据就不声称自动发现真实吊销。
- 绝不默认把全部 `BOUND` 支付改为 DENY。现有支付 P3 两级准入是业务授权边界，只有另外明确批准更高保证策略时才可以改变。若晋级不足仅降为 `BOUND`，P3 仍可能允许，测试必须明确区分“身份保证降级”与“付款被拒绝”。
- 与H81既有原件及历史回归精确比对；变更需新的源基线及新的冻结任务，不能修改旧H82十五项SOURCE_LOCK。
