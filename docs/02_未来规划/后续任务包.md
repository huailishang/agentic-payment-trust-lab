### 步骤 1：TE02 规范化契约【已完成：PASS】

**主域：可信执行域**

唯一问题：

> 支付域的 `Order` 等真实对象怎样转换成稳定、可重复哈希（Hash）的规范化表示？

必须冻结：

- `Decimal` 精度和字符串表示。
- `datetime` 时区和格式。
- tuple/list 是否等价。
- 字段缺失与 `null` 的区别。
- Unicode 规范化。
- 对象/映射字段顺序。
- `items` 顺序是否属于业务语义。
- 版本字段是否进入摘要。

交付：

```text
canonicalize(value) -> JSON 兼容的规范化值
canonical_json(value) -> str
canonical_hash(value) -> str
正向测试 + 篡改/等价表示负向测试
```

禁止：本包不得修改 S09 的重新确认或拒绝逻辑。

2026-07-27 已完成：新增 `canonicalize()`，真实 `Order` 可直接进入规范化；专项 18/18 PASS，全量回归 118/118 PASS。具体契约与边界见 [S12 与 TE02 执行记录](../04_验证体系/S12与TE02执行记录_20260727.md)。

### 步骤 2：TE03 绑定接口 + S09 首个跨域接入【已完成：PASS】

**主域：可信执行域 + 支付域**

唯一问题：

> 已授权订单与最终订单是不是同一个被绑定对象？

可信执行域提供：

```text
verify_binding(expected_digest, actual_object)
-> 有效（VALID） / 无效（INVALID） / 证据缺失（MISSING_EVIDENCE）
```

支付域消费这个事实，但仍自行决定：

```text
价格变化 -> 是否重新确认
商品变化 -> 是否拒绝或重新确认
非关键字段变化 -> 是否继续
```

验收重点：

- S09 原有业务结果不能因为换成哈希/绑定实现就被重新定义。
- 哈希不同不能自动等于 `DENY`。
- 同一语义的等价对象表示不得因序列化差异产生假变化。
- S01—S12 全量回归无新增失败。

2026-07-27 已完成：新增 `verify_binding()` 与 `VALID / INVALID / MISSING_EVIDENCE` 结构化事实；S09 已真实消费绑定摘要与状态证据，同时保留原有字段级业务裁决。专项与界面测试通过，第二轮全量回归 128/128 PASS。具体见 [TE03 绑定与 S09 接入执行记录](../04_验证体系/TE03绑定与S09接入执行记录_20260727.md)。

### 步骤 3：TE04 执行身份 / 状态观察 / 幂等事实 + S12 接入【已完成：PASS】

**主域：可信执行域 + 支付域**

从 `payment_recovery.py` 中逐步抽出通用事实验证：

```text

```

可信执行域只回答：

- 查询到的状态是否绑定原 `payment_id / provider_ref / order_id`。
- 请求（request）/ 交易（transaction）/ 幂等（idempotency）边界是否一致。
- 是否出现冲突、重复或缺失证据。

支付域继续决定：

- 等待。
- 再次查询。
- 进入安全重试候选。
- 人工介入。

禁止把“幂等检查通过”直接等同为“允许再次扣款”。

2026-07-27 已完成：新增执行身份、状态观察与幂等事实接口；S12 已消费状态观察绑定事实，FAILED 恢复分支已消费幂等边界和同请求相关尝试清单；支付恢复策略仍留在支付域。第一遍全量回归 137/137 PASS。具体见 [TE04 执行事实与 S12 接入执行记录](../04_验证体系/TE04执行事实与S12接入执行记录_20260727.md)。

## 3. 当前执行方式

下一阶段不再以“一个 S 编号 = 一个开发包”为唯一推进方式，而以模块闭环为主：

```text
先做可交互输入
    -> 后端真实重新计算
    -> 同一评测器跑内部回归 + 外部挑战
    -> 记录错误放行 / 错误拒绝 / 漏确认 / 禁止副作用
    -> 外部案例暴露缺口
    -> 再补最小字段或可信能力
```

每个改动仍要满足：专项测试 + 全量回归；不能为了接 benchmark 反向改坏支付域与可信执行域的职责边界。

## 4. 当前明确不做

- 不按顺序继续铺开 S14—S20。
- 不一次性创建所有可信执行模块。
- 不提前设计大而全的协议/支付/身份字段模型。
- 不在主 UI 堆协议字段、证据对象和原始 JSON；技术内容默认折叠为开发者信息。
- 不直接克隆和运行所有外部 benchmark；先借案例、Schema 和评分方法。
- 不在没有明确消费者前抽成公共开发工具包（SDK）或远程服务。
- 不引入真实支付凭证、生产密钥、真实资金或主网操作。
