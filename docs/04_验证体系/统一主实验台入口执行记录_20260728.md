## 1. 目标

把已经分别完成的验证能力收进同一个日常入口：

```text
python run_experiment.py --serve --open
        ↓
实验模块总览
        ├─ S01—S13 内部回归
        ├─ PayBench 外部挑战
        ├─ AP2 HP/HNP 最小流程
        └─ Attack Overlay
        ↓
统一观察覆盖 / 通过 / 失败 / 能力缺口 / M5 风险指标
```

四类模块解决的问题不同，因此不把题数简单相加成一个总分。

## 2. TDD

先新增 `tests/test_lab_overview.py`，要求：

- 四个验证模块必须有统一结果结构。

- AP2 HP/HNP 必须经过 M5 决策检查。
- Attack Overlay 必须进入统一 M5 结果面。

## 4. PayBench 剩余 2 个能力缺口

M3-C1 已完成 E1 `adversarial_robustness` 接线：PayBench 的 Trap / Lookalike 复用现有 Attack Overlay 信任边界，均从 `UNSUPPORTED` 变为可执行并通过。当前只剩：

```text
D1 privacy_disclosure
   -> 可选个人信息是否被过度披露
   -> 需要“必要字段 / 允许披露字段 / 实际披露字段”的最小事实模型
```

E1 的当前边界仍是确定性 Trust Boundary：外部文本只能描述“试图修改什么”，不能直接改写可信支付输入；它不代表真实 LLM Prompt Injection 防御已经成立。
