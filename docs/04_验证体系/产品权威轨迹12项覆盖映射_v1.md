# 产品权威轨迹 12 项覆盖映射 v1

## 1. 当前结论

固定项目级任务 T01—T12 当前均没有产品 outcome 直接携带统一 `ProductAuthoritativeTrace`：

```text
product-observed authoritative trace = 0/12 VALID
GESR = 0/12
```

runner 或测试事后合成的 Replay 只用于诊断，不计入产品轨迹。

结构化覆盖证据：

- `P9_PRODUCT_AUTHORITATIVE_TRACE_MINIMUM_CONTRACT_REPAIR_V1/evidence/EV-06-coverage-repaired.json`
- 一致性键：`(entity_type, entity_role)`
- 当前 12 项状态：全部 `NOT_AVAILABLE`

## 2. 统一映射口径

每项记录：

```text
产品入口 / outcome
→ 真实 source objects
→ entity roles
→ 直接解释最终 decision 的事件
→ profile 事件顺序
→ 缺失事件
→ 最小插入点
→ stable-ref strategy
```

统一 stable-ref：

- 有原生 ID：`<type>:<id>[:<version>]`；
- 无原生 ID：`<type>:sha256(canonical-json(projection-schema/v1))`；
- RESULT：hash outcome projection，排除 `authoritative_trace`；
- 不使用当前时间、内存地址、随机值和文件路径。

## 4. T02—T04 双订单快照

三项都必须同时记录：

```text
AUTHORIZED_ORDER_SNAPSHOT = Order:<order_id>:webshop-v1
CURRENT_ORDER_SNAPSHOT    = Order:<order_id>:<mutation-specific-v2>
```

两者与同一个 `ValidationResult` 建立 `VALIDATED_AGAINST` 关系。

### T04 修正

T04 的 `order_differences` 实际为空。真实依据来自：

- authorized/current Order；
- `ValidationResult.evidence`；
- confirmation/order binding evidence。

因此本映射删除了不存在的 `OrderDifference` source object。

## 5. T05/T06 最终决策

```text
T05:
PREPAYMENT_DECISION_RECORDED = ALLOW
ACTION_BINDING_DECISION_RECORDED = INVALID → DENY

T06:
PREPAYMENT_DECISION_RECORDED = ALLOW
ACTION_BINDING_DECISION_RECORDED = MISSING_EVIDENCE → INDETERMINATE
```

`ACTION_BINDING_DECISION_RECORDED` 的来源必须是现有 `GovernedActionBindingFact`，轨迹层不得重新运行 binding。

## 7. 当前缺口与阶段拆分

所有 12 项的产品公开 outcome 当前都没有统一 `authoritative_trace`，因此均为：

```text
current_status = NOT_AVAILABLE
missing_events = all_product_events
new_business_rule_required = false
```

后续不能直接进入 T10 产品实验，必须先完成独立 measurement adapter：

```text
阶段 A：runner 支持新 envelope，但产品仍不产出 trace
→ 重新冻结 0/12 BEFORE 和新 runner hash

阶段 B：同一新 runner，只让 T10 产品 outcome 产出 trace
```

## 8. 设计边界

轨迹只记录和核对现有事实，不新增金额、payee、授权、Agent、Executor、Payment、Policy、Lineage、Recovery 或 Conflict 业务判断。

本映射不实施代码修改，不改变当前 `0/12 VALID` 基线。
