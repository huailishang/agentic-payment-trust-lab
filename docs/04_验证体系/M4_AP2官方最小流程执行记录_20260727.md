# M4 AP2 官方最小流程执行记录

> 日期：2026-07-27

## 1. 本轮目标

验证本项目不仅能处理自己设计的场景 JSON，还能把外部协议对象映射到现有协议中立模型，并继续复用同一套支付判断规则。

```text
AP2 官方最小流程对象
        ↓
AP2 Flow Adapter
        ↓
IntentMandate + TransactionRequest
        ↓
现有 Validator
        ↓
ALLOW / DENY / CONFIRMATION_REQUIRED / INDETERMINATE
```

外部协议只负责提供事实和授权边界，不反向改写 Payment Domain 的核心业务规则。

## 2. 固定的官方来源

本轮固定：

```text
项目：google-agentic-commerce/AP2
Release：v0.2.0
Commit：b4587ac
许可证：Apache-2.0
```

选择该版本的原因：v0.2.0 已包含 Python SDK，并加入 Human-Not-Present 样例，同时更新 Human-Present 样例。

当前不安装完整 AP2 SDK / Google ADK / Gemini，也不使用真实卡、真实 DPAN、真实密钥或生产支付环境。

## 3. 两个最小流程

### 人在场（Human-Present，HP）

```text
用户提出意图
    ↓
形成 CartMandate
    ↓
用户确认最终购物车和支付
    ↓
PaymentMandate.user_authorization 存在
    ↓
进入本项目现有 Validator
```

本地固定快照：

```text
samples/protocol_snapshots/AP2_v020_HP_cards.json
```

正常结果：

```text
Adapter READY
realtime_confirmation_required = true
realtime_confirmation_satisfied = true
Decision = ALLOW
```

反例：删除 `user_authorization` 后：

```text
Decision = CONFIRMATION_REQUIRED
Issue = ap2_user_confirmation_required
```

### 人不在场（Human-Not-Present，HNP）

```text
用户提前授权 IntentMandate
    ↓
等待触发条件
    ↓
trigger_condition_satisfied = true
    ↓
无需交易时再次找用户确认
    ↓
进入现有 Validator
```

本地固定快照：

```text
samples/protocol_snapshots/AP2_v020_HNP_cards.json
```

正常结果：

```text
Adapter READY
realtime_confirmation_required = false
preauthorization_present = true
trigger_condition_satisfied = true
Decision = ALLOW
```

反例：没有捕获到预授权证据时：

```text
Decision = INDETERMINATE
Issue = ap2_preauthorization_missing
```

这里的 `authorization_evidence` 是本项目用于离线实验的本地证据包装，不是声明为 AP2 官方字段。

## 4. 新增的绑定检查

M4 不只检查“字段能不能读出来”，还检查 AP2 对象是否互相指向同一笔交易：

```text
CartMandate.payment_request.details.id
        =
PaymentMandate.payment_details_id
        =
PaymentResponse.request_id
```

同时检查：

```text
Cart total = PaymentMandate total
Cart merchant = PaymentMandate merchant_agent
Intent / Cart 的 confirmation 要求一致
```

例如把 `payment_details_id` 改成另一笔支付：

```text
payment_details_id_mismatch
    ↓
Adapter NOT READY
    ↓
Decision = INDETERMINATE
```

不会为了继续运行而强行拼接两笔不同交易。

## 5. 当前没有假装完成的能力

M4 明确保留以下限制：

```text
不验证 AP2 加密签名
不验证 Merchant Authorization 真伪
不验证 User Authorization 真伪
不验证 IntentMandate 签名链
不机器理解自然语言 Intent 是否真的满足
不执行真实付款
不是 AP2 Conformance Test
```

因此本轮证明的是：

> AP2 v0.2 的两个最小授权流程，可以进入项目现有协议中立模型并保持授权边界。

不是证明：

> 本项目已经完整实现 AP2 或已经具备生产支付能力。

## 6. 可运行入口

```text
python scripts/validation/run_ap2_protocol_samples.py
```

默认生成：

```text
artifacts/ap2_v020_flow_report.json
```

当前结果：

```text
HUMAN_PRESENT      PASS  ALLOW
HUMAN_NOT_PRESENT  PASS  ALLOW

2/2 PASS
```

这两个 PASS 指固定离线流程映射与规则执行通过，不是外部官方认证分数。

## 7. TDD 验证

M4 新增的核心测试：

```text
HP + 用户授权              -> ALLOW
HP + 缺用户授权            -> CONFIRMATION_REQUIRED
HNP + 预授权 + 触发满足    -> ALLOW
HNP + 缺预授权             -> INDETERMINATE
Payment / Cart 绑定不一致  -> INDETERMINATE
CLI 两条固定流程           -> 2/2 PASS
```

旧版 AP2 snapshot adapter 的原有测试继续通过，说明本轮没有用新流程适配器替换旧实验，而是新增更接近 AP2 v0.2 Mandate 流程的最小切片。

最终回归：

```text
M4 AP2 固定流程：2/2 PASS
M3 PayBench：6 supported / 4 unsupported；支持部分 6/6 PASS
M2 内部回归：13/13 PASS + baseline PASS
全量自动测试：178/178 PASS
```
