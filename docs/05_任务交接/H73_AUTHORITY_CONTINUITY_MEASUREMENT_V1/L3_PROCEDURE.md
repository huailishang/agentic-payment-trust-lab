# H73 Independent Evaluator procedure

1. 验证SUBMISSION的每个文件摘要及L2 gate摘要，完整性只读通过后保存接受快照。确认L2来自公共runner且六项成功、无历史文件变化。REPORT必须包含原/最终git status、任务diff或新增文件清单、累计成本和受限项。
2. Evaluator开独立账本evidence/l3_review/COST.json，schema与Executor账本相同，只含Evaluator工作窗、l2_attempts=0、l3_attempts先0、全0外部动作；正式L3前递增为1。不能回写Executor提交账本，CHECK final合并两者核150/105/45上限。
3. 从锁定原源直接重建四旅程时序，不先接受ANALYZE的结论。逐项回读矩阵全部决定性引用和全部12边界；复算两个白名单私有材料结构、业务标识摘要与跨源join。记录独立SOURCE_REVIEW.json：每边界结论、所读source/pointer/lines、支持/冲突/无法判定及理由，不公开原始ID/本机路径。
4. 核任务许可/领域确认/外部付款层次及原始/续授/重建区分。N01的负责人续行原话必须纳入竞争解释；缺原确认时刻不得由创建session时刻推算。C01无付款，R01恢复不要求新付费授权，D01边界不升级。
5. 若建议能力建设，独立核每个共同断点。至少两个独立历史边界/旅程的证据，不能只重复同工厂静态特征。读不到其他私有来源只能INPUT_LIMIT；公开审计产物没记录与真实错放行必须分开。评估最小接缝是否有现成消费者和有判别力的同基线对照。
6. 在隔离内存副本加入至少两个独立损坏：把已知续行许可改称真实用户身份认证；把UNKNOWN原时间改为确定EXPIRED。检查机器或语义程序能拒绝，记录采用哪种判定及理由。不得修改原RESULT或源，也不得把人工审阅伪装成自动测试。
7. 用冻结YAML和公共runner --mode evaluator --out 本包evidence/l3_review/gate_001运行唯一六项L3；保存三件套。再确认接受文件完全未改。L3结构全绿仍须AC-01至06各自二值验收，任一强制项不可核验不得PASS。
8. 完成REVIEW，区分验证结论、影响NOT_APPLICABLE、下一步四分支。关闭Evaluator成本窗，补列执行/评估/制包费用及剩余，保留账本与原UNKNOWN。不重复正式L3；收尾可作只读成本/文档检查。必要时另冻最小能力包，不自动实施。
