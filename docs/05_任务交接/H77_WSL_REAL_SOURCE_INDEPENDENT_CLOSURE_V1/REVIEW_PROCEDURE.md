# H77 独立复核要求

1. 先从r129地图给出全局位置。H76只是有正向历史技术事实，原Docker合同未获签收，不能用本包回改。读取REVIEW和preparation/ASSESSMENT，核3轮与补充2轮边界偏差的披露；该2轮不是负责人原话，不能补造授权或成本。
2. 接受前核L2完整六组EV三件套、所选L2路径、报告及实现白名单。读RUN/WORKLOAD/TASK_TESTS，确认无隐式发行预演、外网下载/安装、合成正例、旧产物覆盖、全局配置/宽泛清理或参数注入。关键guard的离线证据必须有实际输出；缺失则拒收，不进入真实L3。
3. 接受快照ACCEPTED.json包含files（repo相对路径→SHA）及l2_gate_path（l2或l2_retry_02中的实际成功L2-GATE）。覆盖全部提交实现/报告/证据、冻结合同/计划/工具/BASELINE/FREEZE；不包含可变CURRENT或未来L3输出，不自包含。记录接受时git status/diff与L2/报告原字节。未接受前不得运行CHECK live。
4. 独立L3只有一次。将路由置READY_FOR_REVIEW/Evaluator，用agent Python运行BOOTSTRAP --mode evaluator；不复用H76旧正例、根或nonce。全过程亲自回查实际Ubuntu命令/发行进程、archive成员及运行二进制摘要、管理根捕获顺序。CHECK返回的布尔字段只是索引，不能替代底层事实。
5. 逐字段人工检查agent-list与entry原始脱敏结构：实际Parent ID来自Server管理结果、注册父ID一致、唯一选择器1001、目标URI精确一致；token派生ID的秘密不可公开。核三进程内核Uid文本、PID/命令、socket、私钥权限；UID1002必须真实RPC拒绝/无SVID。缺失原始结构不能由SOURCE.json非空字段抵消。
6. 独立用原验证器与密码学复算正例及原10负例；金额/用户意愿/实际撤销未测，过期观察是模拟。原130回归必须全部断言通过。任一零容忍反例马上停止、保全、清理；不能修验收器/实现再重跑L3。
7. 回查独立清理命令、每个本次PID/启动标识/专属路径及公开私钥扫描；无Docker隔离、无管理员抵抗能力等剩余边界明确。复算接受快照不变、原H76字节保持，账本包含失败和UNKNOWN成本。公共Runner会顺序继续执行检查，即使VP-02失败，之后命令也只能读已有产物/清理/回归，不得隐式启动第二次运行。
8. 逐AC通过/不通过并引用RV-EV与人工原始回查。必要证据无法客观复现时写“无法复核，建议人工抽查”，强制AC不通过。任务结论、项目影响、继续价值分别判断；全通过仅PASS/IMPROVED受控实际来源切片并停止同类扩展。不能宣称E整体闭合或监管合规。最终再比较生命周期测量与真实消费者/用户身份方向，条件未满足不先做能力建设。
