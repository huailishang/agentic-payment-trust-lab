# M2 内部回归基线执行记录

> 日期：2026-07-27

## 1. 本轮完成什么

把 S01—S13 固化为内部最小回归集，用于防止后续修改把已经验证过的能力改坏。

```text
S01—S13 当前正确结果
        ↓
冻结成 internal_baseline_v1.json
        ↓
以后每次运行重新计算
        ↓
逐字段与基线比较
        ↓
PASS / FAIL + 具体差异路径
```

基线文件：

```text
samples/regression/internal_baseline_v1.json
```

核心实现：

```text
src/agentic_payment_experiment/regression_baseline.py
```

## 2. 基线比较什么

只比较会影响业务行为和评测结果的稳定字段，包括：

- 预期决策、原因代码、证据代码、禁止副作用。
- 实际决策、原因代码、证据代码、订单差异。
- M5 六类统一评测结果。
- 实际副作用。
- 生命周期关键状态和恢复动作。
- 支付恢复关键状态、是否允许重试、下一动作。

展示标题、教学文案、流程说明等 UI / presentation 字段不进入基线，避免纯文案修改产生误报。

## 3. 日常使用

直接运行：

```text
python run_experiment.py
```

正常结果会同时出现：

```text
Summary: total=13 passed=13 failed=0
内部回归基线：PASS
```

并落盘：

```text
artifacts/internal_regression_report.json
```

报告包含：

```text
status
baseline
scenario_count
differences
```

如果后续代码把 S01 的实际决策从 `ALLOW` 改成 `DENY`，会返回非 0 状态，并指出类似：

```text
scenarios.S01.actual.decision: expected='ALLOW' actual='DENY'
```

## 4. 基线更新原则

基线不是“测试失败后自动覆盖”。

```text
发现差异
  ↓
先判断是回归还是有意设计变化
  ↓
回归 -> 修代码
有意变化 -> 人工审查原因和影响
  ↓
确认后再更新 baseline v1 或新建下一版本
```

这样避免把错误结果直接写成新的“标准答案”。
