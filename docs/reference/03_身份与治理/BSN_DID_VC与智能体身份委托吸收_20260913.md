# BSN DID / VC 与智能体身份委托：项目吸收结论

## 一句话结论

BSN 的主要参考价值不是“把支付上链”，而是补齐 `责任主体 → Agent → 委托 → 行为` 的可验证关系。BSN DID / VC 只作为身份 Provider 候选，不成为支付项目或 Control Plane 的中心依赖。

## 对当前项目的映射

```text
Principal Identity
→ Agent Identity
→ Delegation
→ Runtime Identity
→ Payment Authorization
→ Binding / Policy / Execution
→ Evidence / Audit
```

当前支付项目已经覆盖后半段 Binding / Policy / Execution / Audit，正在 B-15B 验证 Credential / Possession，因此本次吸收直接并入现有 H-28，不新开平行身份支线。

## 候选能力定位

- W3C VC / DID：作为 credential / issuer / verifier 的标准数据模型参考。
- SPIFFE / SPIRE：优先验证 workload / executor 的 Runtime Identity。
- BSN DID / VC：作为中国区实名、组织身份与可验证凭证 Provider 候选。
- 企业 IAM / CA：未来真实企业环境中的另一类 Provider。

具体 Provider 必须映射为统一 Facts，再进入现有 Trust Gate；不得因为存在 DID、VC 或证书就自动提升为支付授权。

## 当前不做

- 不建设区块链节点或 DID 网络；
- 不把支付记录全量上链；
- 不把 BSN 写入支付 Core；
- 不把 `credential_ref` 相等提升为 `VERIFIED`；
- 不接真实生产身份、真实资金或 live Provider。

## 与 H-28 的关系

H-28 继续冻结四类证据：credential validity、subject binding、proof-of-possession、freshness/replay。新增 BSN / W3C VC 只用于补充 Principal / Agent credential 与 issuer / verifier 语义；第一实现候选仍由 H-28 根据可机械验证性选择，不预设必须采用 BSN、SPIFFE 或 DPoP。
