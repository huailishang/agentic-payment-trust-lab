## 1. 已实现事实

新增 `trusted_execution/confirmation.py`：

- `ConfirmationRecord` 保存 confirmation、authority、授权订单引用、确认时 Hash、确认时间、过期时间和状态；
- `confirmation_order_payload()` 只投影用户确认的交易内容：merchant、payee、items、金额、币种、服务与履约条款；不把 order version 当作 Hash 的替代品；
- `verify_confirmation_binding()` 在付款前重新计算 Hash，返回 `VALID`、`INVALID` 或 `MISSING_EVIDENCE`，并记录 `reason` 与 `invalidated_by`；
- `execute_with_confirmation_gate()` 仅在 `VALID` 时调用支付回调。`INVALID` 映射为 `CONFIRMATION_REQUIRED`，证据缺失映射为 `INDETERMINATE`。

这保持了边界：可信执行域先给出绑定事实，支付域的闸门才映射动作；Hash 不被表述为防篡改存储、身份认证或生产支付安全。
