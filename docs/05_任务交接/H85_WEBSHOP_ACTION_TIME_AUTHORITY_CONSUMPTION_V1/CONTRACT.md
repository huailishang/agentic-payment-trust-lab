## Single objective

在同一受治理 WebShop 入口，把按次获取身份资格的责任交给消费入口的受控调用代码。该入口根据已经建立的 `GovernedPaymentAction` 和原订单、授权版本、请求及付款引用，绑定一次来源观察、原验证器 Fact、入口持有的时钟以及原 WebShop 门禁。测试编排仅启动隔离来源并执行测试登记变更。测试编排不得为付款入口提供预先判定的来源结果、Fact 或自报当前时点。

可证伪假设是，同一入口在来源发放有效时能自动得到 VERIFIED，明确拒绝或无法确认状态时保持 BOUND，且原付款与确认守护保持。独立复核须能沿原始观察与动作关联记录复算。若结果仍只能由测量驱动手动选 Fact，或需要扩大到共享 P3、PSP、业务准入与凭据生命周期，当前假设失败，保留原路径并停止。

## Allowed scope

- 一个入口的显式实验模式，允许改动 `scripts/validation/webshop/run_same_journey_responsibility.py` 及最多一个同目录、只服务该入口的采集接缝模块 `action_time_authority.py`。
- 执行者可新增本任务的 `CANDIDATE.py`、`candidate/` 支持文件、`REPORT.md` 与当次执行证据。允许复制已锁 H84 的采集和清理材料至 `candidate/`，逐项保留来源摘要与必要差异。合同、检查器、计划、输入锁以及既有证据在执行阶段只读。允许评估者维护 CURRENT 和地图。
- 原 H81/H83/P3/P2/P4、WebShop 产品门禁、旧测试、旧工作区变动、H84 原件只读。未启用实验模式的同旅程入口与既有接口行为须保留。单个 UID、同一隔离 socket 和已锁定 SPIRE 1.16.0，继承私钥隔离与归属清理。作用域仅本地模拟。

## Exclusions

用户授权撤销、轮换、证书全局吊销、外部可信授时、强认证和生产采用留待各自独立证据。禁止改变 BOUND 准入、授权、确认和幂等规则，禁止复制验证器、引入通用凭据框架或增加第二消费者。真实资金、外部测试支付、生产或外部 API、外部网络访问、下载、安装、Git 提交推送和历史改写均为零。禁止向公开证据写入私钥、令牌或可重用秘密。

## Execution sequence

1. **S0 先验证最难前提。** 固定同旅程入口的现有输入、未接线基线和时钟读取责任。离线确认入口能在不破坏原调用的情况下，于付款门禁前通过一个受保护的本地取证接缝拿到同 UID 响应。检查实际参数来源。若只有父测试脚本能选择输入、没有可观察的原生动作绑定，或同旅程入口需要新增外部资源，则停止，记录具体缺口，不进入现场。
2. **S1 只建设该入口。** 保留原动作构造、确认及 P2/P3/P4；入口为每个动作创建新观察并把来源返回、签名验证、该动作和入口时点关联。当次 Fact 只从原验证器产生。隔离不同动作的模拟支付存储。对未启用实验模式的同一入口做等价对照。
3. **S2 先完成离线守护。** 以同业务快照比较正常资格、本轮来源不可得和时点关联失败；运行原 86 项回归。命令不可用、结果不稳定、服务范围或权限漂移时停止。允许最多两版实现及在各自额度内修任务脚本，无需逐步人工复核。
4. **S3 只用一次现场窗口。** 在冻结前置、角色授权和相同候选哈希均成立时，记录本次消费入口上的正常样本，执行一次隔离登记删除，观察明确拒绝，由同一入口消费本次动作自己的状态响应。删除后观察次数包含该动作取证，总计至多 12 次。不得注入现成 Fact、替入测量驱动结果或改原本付款策略。失败即保留原件并清理，现场不重启、不追加。任一前置失败必须由现场入口拒绝执行，即使公共 runner 仍调用后续条目。
5. **S4 一次统一交付。** 执行者交全部原始证据、对照差异、预算和 L2。评估者接受同一快照，独立跑唯一 L3，重算签名、动作关联、回调数、时点及清理，逐 AC 签收。有明确未知或零容忍反例时停止该轮。
